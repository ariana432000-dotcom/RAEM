# CLAUDE.md (web/)

Rules for turning Figma designs into code, and code into Figma, for the **RAEM Forecast Console** in this folder. This folder is self-contained: `backend/engine/` holds a copy of the forecasting code and its data (refresh it with `backend/tools/sync_engine.py` from the research project, whose own rules are in that project's CLAUDE.md). This file covers the UI and the web app.

## What this UI is

A single self-contained HTML page (published as a claude.ai Artifact) that replays results exported from the project's Python code: daily BUY/HOLD/SELL signals, 7-day forecasts from 14 models, backtest, memory, LLM analyst sessions and more. It has **no framework, no bundler and no backend**. Everything is one `<style>` block, plain JavaScript that builds HTML strings, and inline SVG. Its look (restyled on 2026-11-15 to follow assetick.com's layout) is a flat dark market dashboard: a solid top nav, a near-black page (`#030712`) and flat 12px-radius cards with a 1px border, no blur and no gradient field; a light theme with white cards stays available. Home is a DSE market overview (index cards, day summary, sector breadth, top 20 shares, news) with the RAEM signals watchlist below it. It began as a hand re-implementation of the AInvest terminal in the `any_with_dse-main` demo (Next.js + Tailwind) and was restyled on 2026-10-20 at the user's request; the Tailwind map in section 2 still describes that demo's vocabulary.

Because it is not a React/Tailwind project, **do not paste Figma MCP's React + Tailwind output into it**. Treat that output as a visual reference and rewrite it with the tokens and helpers below.

## 1. Design system structure

### Token definitions

All tokens are CSS custom properties at the top of `src/template2.html`, in one theme triplet (light-first):

```css
:root { --bg:#eef0fb; --panel:#ffffffb8; --text:#141a33; --accent:#4350f0; ... color-scheme: light; }
@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) { ...dark values... } }
:root[data-theme="dark"] { ...dark values again, so the toggle wins both ways... }
```

Rules:
- Every token is first defined on bare `:root` (light). The media block and the `[data-theme="dark"]` block only **redefine** tokens, and they must stay identical to each other.
- `body` keeps `background: var(--bg)`. There is no gradient field and no `backdrop-filter` anywhere.
- Panels are flat and opaque (`--panel`). Overlays that sit above content (tooltips, the "More" menu, the mobile sheet, chart dot outlines) use `--solid`.
- No colour literals in components. The only literals allowed are inside the token blocks.
- Theme state: `data-theme` on `<html>` is `dark`, `light` or absent (system). `settings.theme` in `src/extra.js` keeps it in `localStorage` (`raem:set`); the default is now `dark` (a saved choice, including "system", still wins).

Contrast was checked on 2026-11-15 (WCAG ratios computed for every text, accent and signal colour on `--panel`, `--bg` and `--bg-raised`, both themes): all at least 4.5:1 for text (lowest: light `--sell` on `--bg-raised` 4.98), control borders `--ctl` at least 3.2:1, `--on-accent` on the accent fill at least 5.1:1. Re-check after changing any token, and add new colours to **all three blocks**.

Typography: Manrope (500 to 800) for text and JetBrains Mono for every figure, ticker and date (`font-variant-numeric: tabular-nums`), loaded from Google Fonts, the only allowed font host, each with a system fallback stack. Headings are weight 800 with tight tracking; the hero title is `clamp(36px, 5.2vw, 62px)` with a gradient on the key phrase. Sizes in use: 11, 12, 13, 14 (body), 16, 18, 24 (stat value), 28 to 40 (page title), up to 62 (hero). Uppercase labels use `letter-spacing: 0.06–0.1em`.

Spacing: 4/6/8/10/12/14/16/20/24px steps; card padding 20px; gaps 12px (stat row), 16 to 28px (stacks). Radius: 12px cards, 12px selects and inputs, 999px buttons, tabs, pills, badges and the search field. There is no token transformation step (no Style Dictionary, no Figma variable sync). Values are hand-copied.

There is no Storybook. The live page is the only documentation. Code Connect does not apply: there is no component file to map a Figma component to. Map by **name** instead (see the Figma section).

### Frameworks and libraries

- UI: none. Vanilla JavaScript, template literals, event delegation on `document` (`src/handlers.js` and the first click handler in the template).
- Styling: hand-written CSS, one `<style>` block, custom properties.
- Build: `src/merge.py` joins `template2.html`, `extra.css`, `extra.js`, `live.js`, `handlers.js` into `template3.html`; `src/build.py` injects the data and writes `frontend/dist/index.html`. Plain string replacement, no bundler, no npm. The template is a page fragment (the artifact viewer adds the document skeleton); `build.py` prepends the skeleton (`<!doctype html>`, charset, viewport, an inline icon) for hosting, because without it a hosted page renders in quirks mode and phones show the desktop layout. Both scripts write LF line endings on every OS (`.gitattributes` keeps the repo LF too).
- Runtime limits come from the Artifact host: external scripts only from cdnjs/jsDelivr/unpkg with pinned versions, stylesheets only from Google Fonts, no `fetch` of other hosts, no downloads, no `alert/confirm`, 16 MB page limit (current build is about 0.8 MB). The page currently loads **one external resource: the Google Fonts stylesheet** (Manrope, JetBrains Mono; see the `<link>` tags at the top of `template2.html`), with system-font fallbacks if it is blocked. Add nothing else.

### Asset management

- No image, video or font files. Everything is inline.
- Data is embedded as two JSON objects replacing `/*__DATA__*/null` and `/*__EXTRA__*/null` in the template. They come from `backend/data/tickers/*.json` (per ticker) and `backend/data/extra.json`.
- No CDN, no image optimisation. If a design needs a raster image, embed it as a `data:` URI and keep it small.

### Icon system

Icons are an inline-SVG path table, `ICONS` in `src/template2.html` (extended in `src/extra.js`), in the Lucide style: 24×24 viewBox, `stroke="currentColor"`, `stroke-width="2"`, round caps and joins. Use them through `ic("name")`, which returns the `<svg>`. Names in use: `dash line chart db clock brain pulse inbox alert moon sun menu star wallet news check file gear`.

To add an icon from Figma: export the SVG, keep only the inner paths, add them to `ICONS` under a short lowercase name, size it with CSS (`width/height: 16px` for nav and stat icons, 20px in the empty state). Do not add an icon font or per-icon files.

### Styling approach

- Plain CSS with class names, no methodology (no BEM, no CSS Modules). Components are single-purpose classes; modifiers are a second class (`.badge.buy`, `.btn.primary`).
- Layout uses flex and grid with `gap`, not per-element margins.
- Global styles: reset, `[hidden]{display:none!important}`, focus ring (`:focus-visible` 2px accent), reduced-motion override, selection colour.
- Responsive: one mobile breakpoint `@media (max-width: 767px)`: the sidebar becomes a slide-over drawer, stat grid goes to 2 columns, rows tighten. `@media (pointer: coarse)` raises touch targets to 44px. Wide tables and code scroll inside `.scroll` (`overflow-x: auto`), never the page. The page must not scroll horizontally at 390px.
- Safe-area insets: side gutters use `max(16px, env(safe-area-inset-left, 0px))`. The `<meta name="claude:viewport-fit-sides">` tag at the top of the template is only valid together with those paddings.

Edit only `template2.html`, `extra.css`, `extra.js`, `handlers.js`. Never edit the generated files.

`lineChart()` accepts `null` gaps, `noline` series (tooltip only) and `opts.band`. The virtual Portfolio page (id `paper`, `localStorage` key `raem:pt`) was removed on request; do not re-add it.

Layout: `.app` is a column of the sticky `.topnav` and the scrolling `#scroller`, which holds `<main class="content">` (max 1180px) and the footer. Home is `renderDash()` in `extra.js`: the "DSE Market Overview" header with Refresh, three index cards (DSEX, DSES, DS30), the market summary stats, sector breadth beside the Top 20 shares (ranked by Value, Volume or Trade), the RAEM forecast-signals watchlist, and the DSE news feed. The market state is `X.mkt`; `loadMarket()` in `live.js` fills it from `GET /api/market` once the server answers, so a static copy (no server) shows an empty-state card in place of the market parts and still shows the watchlist. Ticker pages show a pill row to switch stock, and the options card collapses after a run. **Stocks** (`renderStocks()`, state `X.stk`): every issue traded on the latest day with search, sector chips and an Analyze button per row, from `GET /api/stocks`. **Stock analysis** (`renderStock()`, page id `stock`, opened by `openStock(code)` from any `data-stk` element): header and a generated summary paragraph, key statistics, a candlestick chart with volume (`drawStockChart()`, hand-written SVG, hover readout), the RAEM analysis card (signal ring and two buttons, **Open forecast** and **Open AI analysis**, that open the last saved result inside the page; a Run RAEM analysis button that uses the existing add-company flow when the company is not on the site). Open forecast shows the company's last run loaded from its CSV files (`GET /api/forecast/saved/{T}`): Last close, Price data to, Daily rows and Models fitted on one line, a price chart with the forecast and its 10 to 90% range, the next 7 days and each model's day-7 price. Open AI analysis shows the last session's summary and the Decision card, with a Details link (bottom right) that goes to the AI Analysis page. Every chart on these pages has the windows 1M, 2M, 3M, 6M, 12M and 2Y (`WIN_OPTS` / `WIN_PILLS` in `extra.js`, in trading days; the Forecast page's history window uses the same list), and Company fundamentals (category, paid-up capital, cash dividend, outstanding shares, shareholding donut, annual and quarterly EPS), from `GET /api/stocks/{code}`. The existing AI Analysis page is unchanged.

Help for non-experts: `GLOSS` in `extra.js` holds every plain-language definition. `hint(GLOSS.key)` puts a focusable "?" with that text next to a heading, `plainSummary()` writes the "In plain words" box above a ticker's result tabs, and the Help page (`renderHelp()`) lists the same glossary. Add new jargon to `GLOSS` first, then reuse it; do not write a second explanation of the same term.

Model set: the site shows five models (N-BEATS, LASSO, Ridge, RandomForest, Theta), the best average rank across the 8 tickers (ARIMA, the sixth, was dropped on 2026-10-28); the page has no model choice. `backend/app/pipeline/export_ticker.py` fits only those (`KEEP_MODELS`) plus the blends (`BLENDS`), so Ensemble, Fusion, Fusion Top 3 and the reviewer are built from the five. `BASE` in `template2.html` lists all 14 labels and the page shows only those present in a run; the `shown` set in `build.py` must match the five models plus the blends (Ensemble, Fusion, Fusion-Top3). The Python project itself still trains all 14; only the website export is narrowed. The 14-model export was backed up in the research project under `.scratch/backup_20261020_ui14models/`.

AI Analysis notes: served by the backend, the page shows `aiLiveCard()` (the connected LLMs only, "Run again", Run / Hold / Resume) and `aiHistoryCard()` (stored runs, Resume on today's held runs), plus `aiEffectCard()` (how the rating moves the forecast), and a run executes the AI pipeline on the server (see Live runs; no notebooks). As a static copy (artifact, static host) it shows the latest saved analysis at once (an info card, `aiEffectCard()` and the results); by the user's choice there is no replay button there. The card title says "Today's AI analysis" with the server date; the pipeline takes the trade date from `datetime.now()`, so the server's time zone decides the day: the Dockerfile and compose set `TZ=Asia/Dhaka`, and `app/core/config.py` drops an IANA `TZ` on Windows (the CRT would read it as UTC) and calls `time.tzset()` elsewhere.

**Evaluation** (page id `eval`, a main nav link; `renderEval()`, state `X.ev`, `drawEval()` in `afterRender()`): the accuracy of the AI analysis' BUY / HOLD / SELL calls, from `EXTRA.evaluation`, which `build.py` reads from `backend/data/evaluation.json` (optional: without it the page shows an empty state). `app/pipeline/export_evaluation.py` (standard library only) merges the trading logs, the session archive and the files in `backend/data/evaluation_inputs/` (later sources win; see the README), keeps one call per company and day, and scores each call within the next 1, 2 and 3 trading days (BUY right if a close is above the entry, SELL if below, HOLD if the same or higher; returns rounded to 0.01% first). A call on a day with no price bar keeps its own date and uses the last close before it (`carried`); a call needs three later closes to be scored, otherwise it is `pending` until a later refresh. Intervals are 95% Wilson. The always-HOLD baseline is shown beside every accuracy, because HOLD is right most of the time. The bars are `evBars()`: HTML rows with a percent-coordinate SVG track, so labels never scale on phones. `refresh.py` runs the export before the page merge, also with `--build-only`; it never fails (an error keeps the old file). Tests: `backend/tests/test_evaluation.py`.

Saved forecast CSVs: after every forecast run `export_ticker.py` writes `backend/data/forecasts/<T>_summary.csv`, `<T>_prices.csv` (the whole price history, up to 2 years) and `<T>_forecast.csv` (every model's 7-day path plus the "Reviewed" row with its low and high) through `app/pipeline/saved_forecast.py`; the newest run overwrites them and the page loads them again on open. A run made before the CSV files existed is written out from its saved page data the first time it is asked for. Tests: `backend/tests/test_saved_forecast.py`.

Page state: the stock section remembers where you were. `X.stk` keeps the open company, its open panel (`panel[code]` is `fc` or `ai`), the chart windows and the section (`sect`, so the Stocks tab returns to the company you were reading; the breadcrumb's "DSE Stocks" returns to the list) in `localStorage` (`raem:stk`); `POS` keeps the scroll position of every page left (`savePos()` and `restorePos()` in `goPage()`, `openStock()` and `openTicker()`); the address hash is `#stock-<CODE>` or `#tk-<T>`. The Forecast page keeps its ticker, tab and overlays when you come back to it.

Page pattern: each page is `renderXxx()` returning an HTML string, registered in `renderExtra()` (or handled in `render()` for `dash` and `tk`). State lives in `S` (ticker pages) and `X` (extra pages). Clicks use `data-*` attributes (`data-t`, `data-act`, `data-ai`, ...) handled by delegation. A page that draws a chart gets a hook in `afterRender()`.

### Commands

Run from this folder (`web/`):

```bash
python backend/refresh.py                      # everything: price top-up, all tickers, extra pages, build
python backend/refresh.py AAPL IBM --no-top-up # some tickers only (about 1-2 min each with 5 models)
python backend/refresh.py --build-only         # rebuild the page from the data already exported (re-scores the Evaluation page first)
python backend/app/pipeline/export_evaluation.py [--check]   # merge logs + archive + evaluation_inputs/, score the calls, write backend/data/evaluation.json
python -m uvicorn app.main:app --app-dir backend --port 8000   # serve the page and the API
python backend/tools/sync_engine.py /path/to/research/project   # bring engine/ up to date
```

The exports read the engine's state (`backend/engine/forecast_log/`, `backend/engine/chroma_memory/`, `backend/engine/notebooks/` (trading logs only), `backend/engine/data/`, `backend/engine/daily_data/`; override the folder with `RAEM_ENGINE`) and write their output only under `web/data/`. `backend/refresh.py` also runs `predictor_lib.top_up_data_csv()` first unless `--no-top-up`, which appends final bars to `backend/engine/data/*.csv` (yfinance; DSE files from the old.dsebd.org day-end archive, `engine/dse_archive.py`), as `daily.py` does. Two side effects come from the project code they call, not from the scripts: `forecast_lib.load_combined_history()` copies new closes from `backend/engine/notebooks/trading_log_*.csv` into `backend/engine/daily_data/`, and `predictor_lib.run_pipeline()` may refresh `backend/engine/cache/`. Neither writes to `backend/engine/chroma_memory/` or `backend/engine/forecast_log/` (the scripts skip `remember_episode`). They need the packages in `backend/requirements.txt`. `export_extra.py` fetches FX rates from the network and stores them under `fx` (paper trading needs it).

The published page is **not** updated by building. After `build.py`, publish `frontend/dist/index.html` with the Artifact tool and the existing artifact URL so the link stays the same; leave out its first six lines (the skeleton `build.py` adds), because the viewer adds its own.

## Live runs (backend)

- **Stocks (`GET /api/stocks`, `GET /api/stocks/{code}`)**: `app/services/stocks.py`. The list reuses the market overview's day-end rows and joins names (`ai_pipeline.market_data._load_dse_company_names`) and sectors. A sector is only on a company's own page, so it is learned when the page is opened and saved in `storage/dse_sectors_learned.json`; `python backend/tools/build_dse_sectors.py` fills all of them (resumable, polite). The detail reads the company page through `dse_layer.fetch_dse_company_snapshot` (sector, category, market cap, paid-up capital, 52-week range, outstanding shares, shareholding, cash dividend), annual EPS from any table on the page with years and an EPS row or column (`parse_annual_eps`), quarterly EPS from the exchange's news ("EPS was Tk. (0.38) for January-March 2025", parentheses are negative), and about 13 months of candles from `dse_layer.fetch_dse_ohlcv_range`. Cached 15 minutes; every part fail-soft. Parsers are tested on fixtures only (`tests/test_stocks.py`): the shareholding labels and the annual EPS table shape of the live page were not reachable when this was written.
- **Market overview (`GET /api/market`)**: `app/services/market.py` reads old.dsebd.org through `engine/dse_archive._get`: the day-end archive for "All Instrument" (walks back from today over Sun to Thu until a day has rows) gives the day totals, advanced / declined / unchanged (price against yesterday's close), the top shares and every traded issue; the front page text gives the DSEX / DSES / DS30 lines (`parse_indices`, a regex over the page text, so an index it cannot find is left out; the page marks the last letter up apart, `DSE<font>X</font>`, read as "DSE X", so the pattern allows a space there) and the exchange's own day totals with the page's "Last update" time (`parse_front_totals`, shown beside the archive totals without claiming why they differ); bdshare `get_all_news` gives the notices. Each part is fail-soft; the result is cached 15 minutes in memory and in `storage/market_cache.json`, and a failed refresh returns the last good copy with `stale: true`. Sector breadth needs `backend/data/dse_sectors.json` (`{"ABBANK": "Bank", ...}`); without it the sector table shows an empty state. Market cap is not in the archive and is not shown. The parsers are tested on fixtures (`tests/test_market.py`); the live page structure of old.dsebd.org was not reachable when this was written, so check a real response after deploying.

- Three kinds of user runs (plus `refresh`), all queued in `app/workers/jobs.py` and stored in `app/db/runs.py` (SQLite, table `runs`):
  - `forecast`: `app/pipeline/export_ticker.py <T> --models a,b --out file`, on the engine's CSV price files. The key is the sorted model list. A run with exactly `config.DEFAULT_MODELS` also rewrites `backend/data/tickers/<T>.json` and rebuilds the page.
  - `analysis`: `app/ai_engine/run_pipeline.py --ticker <T> --provider <p> --model <m> --out file [--market --name]`. It runs `app/ai_pipeline/runner.py` (`PipelineRunner`, ported from the any_with_dse app) in one process for **any** ticker: no notebook, no per-company file, no preparation step. 17 steps: Outcome Backfill, Fundamentals, Market, News, Sentiment, Macro Regime, Graph Analyst, Bull vs Bear Debate, Investment Facilitator, Episodic Memory, Post-Mortem Review, Trader Proposal, Risk Debate, Risk Facilitator, Portfolio Manager, Decision Verifier, Save Episode. `SessionLog` (`logger.py`) writes `trading_log_<T>.json` in the format `sessions.py` reads, which then goes into `extra.json` via `sessions.ai_entry`. The run key is the bare model for Ollama and `provider:model` for the cloud (`config.llm_key`). `POST /api/analysis` takes any valid ticker, plus optional `market` and `name`; a ticker with no prices yet is fetched by the pipeline itself (yfinance, or old.dsebd.org for DSE: `engine/dse_archive.py`; www.dsebd.org and bdshare answer 410). ## 2. Figma integration rules

1. **Start from tokens.** Read the Figma file's variables and map them to the table above. Figma variable names should mirror token names: `color/bg`, `color/panel`, `color/border`, `color/text`, `color/muted`, `color/faint`, `color/accent`, `color/buy`, `color/sell`, `color/hold`, with `Dark` and `Light` modes. 5. **Signal colours mean something.** Green, red and amber are only for BUY, SELL, HOLD, positive, negative and warning. Never use them as decoration. Direction is also shown by a sign (`+`/`−`) and text, never by colour alone.
